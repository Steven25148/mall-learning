## api文件夹放什么

**`api` 或 `apis` 文件夹，一般放“调用后端接口的函数”。** 你这个项目叫 `src/apis`。

通常按业务拆分：

```
src/apis/
├─ admin.ts      登录、退出、管理员管理
├─ product.ts    商品查询、新增、修改、删除
├─ order.ts      订单查询、取消、发货
└─ brand.ts      品牌查询、新增、修改、删除
```

例如 `product.ts` 可以写：

```
import http from '@/utils/http'

// 查询商品列表
export function getProductList(params) {
  return http({
    url: '/product/list',
    method: 'GET',
    params,
  })
}

// 删除商品
export function deleteProduct(id) {
  return http({
    url: `/product/delete/${id}`,
    method: 'POST',
  })
}
```

页面中需要查询商品时，直接导入调用：

```
import { getProductList } from '@/apis/product'

const result = await getProductList({
  pageNum: 1,
  pageSize: 10,
})
```

**这个文件夹重点描述三件事：请求哪个地址、用什么方式、传什么参数。** 页面布局放在 `.vue` 文件，用户状态放在 Store，通用请求处理放在 `http.ts`。

它的文件名和拆分方式由开发者决定，不要求和后端 Controller 一一对应。

## strore和router放什么

**`stores` 放多个页面共享的状态，`router` 放页面地址和跳转规则。**

**`stores`：管理跨页面需要用到的数据**

你项目中的例子：

```
src/stores/
├─ user.ts         用户信息、Token、登录和退出方法
└─ permission.ts   根据用户权限生成可访问的路由
```

比如登录成功后：

```
登录页面 → 把 Token、用户信息存到 user Store
                       ↓
首页读取用户名，显示“欢迎你”
请求工具读取 Token，放进请求头
路由守卫读取登录状态，判断是否放行
```

Store 除了保存数据，也可以提供修改数据的方法，比如你看过的 `userLogin()`。

**只在当前页面使用的数据，通常不用放 Store。** 例如登录框的输入值、按钮是否正在加载，放在登录页的 `ref`、`reactive` 中即可。Store 默认也不代表刷新后数据会保留，需要额外配置持久化。

**`router`：管理网址对应的页面，以及能不能进入**

你项目中主要有：

```
src/router/
├─ index.ts    路由定义：哪个地址显示哪个组件
└─ guard.ts    路由守卫：跳转前检查登录状态等
```

`index.ts` 中例如：

```
{
  path: '/login',
  component: () => import('@/views/normal/login/index.vue')
}
```

表示访问 `/login`，就显示登录页。

`guard.ts` 则负责这样的规则：

```
访问商品页面
    ↓
有没有登录？
    ├─ 有 → 进入商品页面
    └─ 没有 → 跳到登录页面
```

把你目前问的几个目录连起来看：

| 目录     | 主要职责                         |
| -------- | -------------------------------- |
| `views`  | 页面长什么样、用户怎么操作       |
| `apis`   | 如何调用后端接口                 |
| `stores` | 跨页面共享什么状态、如何更新     |
| `router` | 地址对应哪个页面、跳转时是否放行 |



## utils放什么

**`utils` 放可以重复使用的工具函数和通用处理逻辑。** 多个页面需要相同能力时，就可以抽到这里。

你这个项目里，例如：

| 文件                | 作用                                     |
| ------------------- | ---------------------------------------- |
| `utils/http.ts`     | 统一发送请求、携带 Token、处理响应和错误 |
| `utils/validate.ts` | 校验用户名、网址等数据                   |

常见项目还会放：

```
src/utils/
├─ http.ts        请求工具
├─ validate.ts    数据校验
├─ date.ts        日期格式化
└─ money.ts       金额格式化
```

例如金额格式化工具：

```
// utils/money.ts
export function formatMoney(value: number) {
  return '¥' + value.toFixed(2)
}
```

商品页、订单页都可以调用：

```
import { formatMoney } from '@/utils/money'

formatMoney(99) // 返回 "¥99.00"
```

和前面几个目录的区别是：

- **`apis`**：具体请求什么业务接口，例如查询商品。
- **`stores`**：保存共享状态，例如当前登录用户。
- **`router`**：管理页面地址和跳转。
- **`utils`**：提供通用能力，例如发请求、校验、格式化。

**只在一个页面用到的小函数，可以先写在页面里；有明确复用价值时，再提取到 `utils`。**

# router相关

你现在要学习的是 Vue 项目中非常重要的一项能力：**读懂 Router（路由）是如何定义、导入、注册、执行，并最终将某个** `.vue` **页面渲染到浏览器中的。**

我已经阅读了你上传的 `index.ts`。我们就以这份真实代码作为教材，不从抽象概念开始，而是建立一套可以用于阅读企业级 Vue 项目的分析方法。

首先给你一个结论：

**你这份** `index.ts` **主要负责定义路由表和创建 Router 实例，但没有展示完整的路由注册与动态加载流程。** 这也是我们需要特别注意的地方。

## **一、先理解 Router 在整个 Vue 项目中的位置**

Vue 项目中的路由工作流程

**main.ts / main.js**

创建 Vue 应用，注册 Router

app.use(router)

**router/index.ts**

定义路由表、创建 Router 实例

**Layout.vue**

页面布局容器

**具体路由组件**

home、product 等

```
<RouterView />
```

根据当前 URL，在对应出口渲染匹配的组件

这里有四个完全不同的概念，需要先区分：

| 概念       | 作用                                             |
| ---------- | ------------------------------------------------ |
| 路由定义   | 声明 URL 对应哪个 Vue 组件                       |
| 路由实例化 | 使用 `createRouter()` 创建 Router                |
| 路由注册   | 使用 `app.use(router)` 将 Router 安装到 Vue 应用 |
| 路由渲染   | 通过 `<RouterView />` 显示匹配的组件             |

这四个阶段共同构成基础的路由运行机制。

## **二、第一部分：Router 的导入**

看你文件最上面的三行：

```
import {
  createRouter,
  createWebHashHistory
} from 'vue-router'

import Layout from '@/views/layout/Layout.vue'

import type { RouteRecordExt } from '@/types/router'
```

分别解释。

### **1. 从 vue-router 导入两个函数**

```
import { createRouter, createWebHashHistory } from 'vue-router'
```

`vue-router` 是 Vue 官方路由库。

- `createRouter()`：创建一个路由管理器。
- `createWebHashHistory()`：决定浏览器地址采用 Hash 模式。

例如：

```
http://localhost:5000/#/pms/product
```

其中：

- `http://localhost:5000` 是网站地址。
- `#` 后面的 `/pms/product` 是 Hash 路由地址。

如果换成 `createWebHistory()`，通常会是：

```
http://localhost:5000/pms/product
```

后者一般需要服务器配合处理前端路由的直接访问与刷新。

### **2. 导入 Layout.vue**

```
import Layout from '@/views/layout/Layout.vue'
```

这里的 `@` 通常通过项目构建配置指向 `src` 目录。

所以一般对应：

```
src/views/layout/Layout.vue
```

`Layout` 是一个 Vue 组件，而不是 Router 库提供的特殊对象。

它通常包含导航栏、侧边栏、面包屑和页面内容区域。

典型后台管理系统布局示意

顶部导航 / 用户信息

侧边菜单

商品管理

订单管理

权限管理

RouterView

商品列表 / 订单详情 / 其他页面

index.vue

示意结构，并非对你尚未上传的 Layout.vue 的实际内容作出断言。

重点是：**Layout 是外层页面，具体业务页面通常渲染在 Layout 内部的** `<RouterView />` **中。**

### **3. 导入 RouteRecordExt 类型**

```
import type { RouteRecordExt } from '@/types/router'
```

这是 TypeScript 的类型导入。

`RouteRecordExt` 看起来是项目自定义的路由记录类型，可能在 Vue Router 自带的路由类型基础上扩展了 `hidden` 等字段。

它的实际定义没有包含在上传文件中，因此需要打开：

```

```

才能确定具体结构。

这里特别需要区分：

```
import Layout from '...'
```

导入的是运行时组件。

```
import type { RouteRecordExt } from '...'
```

导入的是类型信息，经过 TypeScript 编译后通常不会成为运行时 JavaScript 导入。

## **三、第二部分：Router 路由表的定义**

这是你整个文件中占比最大的部分。

你的代码定义了两张路由表：

```
export const constantRouterMap: RouteRecordExt[] = [
  // ...
]

export const asyncRouterMap: RouteRecordExt[] = [
  // ...
]
```

你可以把路由表理解成：

**一个规定「什么路径对应什么页面」的配置数组。**

### **1. constantRouterMap：基础路由表**

代码中的结构可以简化为：

```
export const constantRouterMap = [
  {
    path: '/404',
    component: () => import('@/views/normal/404/index.vue'),
    hidden: true
  },
  {
    path: '/login',
    component: () => import('@/views/normal/login/index.vue'),
    hidden: true
  },
  {
    path: '',
    component: Layout,
    redirect: '/home',
    children: [
      {
        path: 'home',
        name: 'home',
        component: () => import('@/views/home/index.vue'),
        meta: { title: '首页', icon: 'dashboard' }
      }
    ]
  }
]
```

这里有三个页面层次：

**constantRouterMap**

/login

登录页，独立路由

/404

错误页，独立路由

/ → Layout

父路由，重定向到 /home

/home

子路由，显示首页组件

这里第一次出现 `children`，它代表嵌套路由。

### **2. asyncRouterMap：另一张路由表**

你文件的第 42 行起：

```
export const asyncRouterMap: RouteRecordExt[] = [
  {
    path: '/pms',
    component: Layout,
    redirect: '/pms/product',
    name: 'pms',
    meta: { title: '商品', icon: 'product' },
    children: [
      // ...
    ]
  }
]
```

它包含的主要业务模块是：

| 父路由 | 业务模块 | 示例子路由     |
| ------ | -------- | -------------- |
| `/pms` | 商品管理 | `/pms/product` |
| `/oms` | 订单管理 | `/oms/order`   |
| `/sms` | 营销管理 | `/sms/coupon`  |
| `/ums` | 权限管理 | `/ums/admin`   |

但是，这里有一个非常关键的知识点：

**路由被定义在数组中，不等于已经注册到 Router 中。**

你上传文件的第 371–374 行是：

```
const router = createRouter({
  history: createWebHashHistory(),
  routes: constantRouterMap,
})
```

注意 `routes`：

```
routes: constantRouterMap
```

这里只传入了 `constantRouterMap`，没有传入 `asyncRouterMap`。

这意味着：单凭这份文件，不能认为 `/pms/product` 已经是可访问的路由。

`asyncRouterMap` 很可能由其他模块根据权限动态添加，但必须继续搜索调用它的代码，才能确认实际机制。

另一个容易混淆的地方是：这里的 `asyncRouterMap` 是项目作者给变量起的名字，并不意味着 Vue Router 会自动把这张表注册进去。

## **四、第三部分：完整解剖一个路由对象**

我们拿你文件中的商品列表路由学习：

```
{
  path: 'product',
  name: 'product',
  component: () => import('@/views/pms/product/index.vue'),
  meta: {
    title: '商品列表',
    icon: 'product-list'
  }
}
```

这是你最需要掌握的部分。

| 属性        | 含义                       | 重要程度 |
| ----------- | -------------------------- | -------- |
| `path`      | 路由匹配路径               | 必须掌握 |
| `name`      | 路由名称，用于按名称跳转等 | 必须掌握 |
| `component` | 对应的 Vue 页面组件        | 必须掌握 |
| `children`  | 嵌套子路由                 | 必须掌握 |
| `redirect`  | 访问某路径时重定向         | 必须掌握 |
| `meta`      | 自定义路由元信息           | 必须掌握 |
| `hidden`    | 项目自定义的隐藏标记       | 理解即可 |

### **1. path：URL 匹配规则**

```
path: 'product'
```

为什么不是：

```
path: '/pms/product'
```

因为它属于父路由：

```
{
  path: '/pms',
  children: [
    { path: 'product' }
  ]
}
```

因此实际匹配：

```
/pms/product
```

`path` 以 `/` 开头和不以 `/` 开头，在嵌套路由中有重要区别。

### **2. name：路由名称**

```
name: 'product'
```

允许使用名称进行跳转：

```
router.push({ name: 'product' })
```

它与下面按路径跳转的方式，在这里指向同一个页面：

```
router.push('/pms/product')
```

路由名称应该保持唯一。

### **3. component：最关键的属性**

```
component: () => import('@/views/pms/product/index.vue')
```

它决定了路径匹配后加载哪个 Vue 文件。

这里的 `import()` 是动态导入。

与：

```
import Product from '@/views/pms/product/index.vue'
```

然后：

```
component: Product
```

相比，动态导入一般会让页面组件按需加载，而不是在应用初始加载时就全部加载。

要注意，**路由的动态导入和路由的动态注册是两回事**。

- 动态导入：何时加载 `.vue` 组件代码。
- 动态注册：何时把一条路由添加到 Router 中。

### **4. meta：路由元数据**

```
meta: {
  title: '商品列表',
  icon: 'product-list'
}
```

`meta` 是 Vue Router 支持的扩展信息容器。

但是 Vue Router 本身并不会自动把 `title` 和 `icon` 渲染成菜单。

必须有其他代码读取这些属性，再生成页面元素，例如：

```
route.meta.title
```

你可以在项目中搜索 `route.meta` 或 `meta.title`，找出谁在使用这些信息。

### **5. hidden：不是路由访问控制**

```
hidden: true
```

在你的文件中，编辑商品、订单详情等路由使用了这个属性。

它通常表示不在侧边栏菜单中显示，并不代表这个页面不能通过 URL 或代码访问。

同时，`hidden` 也不是 Vue Router 内置的权限控制字段。它到底如何生效，取决于项目中的菜单生成代码。

## **五、第四部分：Router 实例的创建**

回到文件底部：

```

  history: createWebHashHistory(),
  routes: constantRouterMap,
})

export default router
```

这短短几行代码实际上做了两件事。

**第一件事：创建 Router 实例。**

```
const router = createRouter({
  history: createWebHashHistory(),
  routes: constantRouterMap

```

这里创建的是整个 Vue 应用要使用的路由管理器。

**第二件事：导出实例。**


导出后，其他文件才能直接导入这个实例。

但是要强调：

它仅仅是 JavaScript 模块导出。

## **六、第五部分：Router 的注册关系**

这部分没有出现在你上传的文件里，但是它是理解整个路由系统的关键。

一个典型 Vue 3 项目的 `main.ts` 可能类似：

```
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

const app = createApp(App)

// 注册 Router 插件
app.use(router)

// 启动 Vue 应用
app.mount('#app')
```

这是典型 Vue 3 示例，不是你上传文件中已经验证的 main.ts 内容。

这里最重要的代码是：

```
import router from './router'
```

它会获取 `router/index.ts` 默认导出的实例。前提是项目的目录解析规则允许 `./router` 指向该文件。

然后：

```
app.use(router)
```

这才是将 Vue Router 安装到 Vue 应用中的关键步骤。

注册完成后，组件才能正常使用 Router 提供的功能，例如 `RouterLink`、`RouterView`、`useRouter()` 和 `useRoute()`。

### **动态路由又是怎么注册的？**

Vue Router 支持：

```
router.addRoute({
  path: '/example',
  component: () => import('@/views/example.vue')
})
```

这可以把新路由动态加入已经创建的 Router。

如果你的项目要注册整个 `asyncRouterMap`，常见写法类似：

```
import router, { asyncRouterMap } from '@/router'

asyncRouterMap.forEach(route => {
  router.addRoute(route)
})
```

但必须分清楚：**上面只是可能的实现方式，不是我在你的文件中发现的实际代码。**

你需要全局搜索 `asyncRouterMap` 和 `addRoute`，确认这个项目是否如此实现，以及它在什么时机执行。

## **七、第六部分：路由怎么让 Vue 页面显示出来？**

假设 Router 已经注册了 `/pms/product`。

用户访问：

```
http://localhost:5000/#/pms/product
```

Vue Router 会匹配：

```
{
  path: '/pms',
  component: Layout,
  children: [
    {
      path: 'product',
      component: () => import('@/views/pms/product/index.vue')
    }
  ]
}
```

匹配之后，预期渲染结构是：

```
App.vue
└── RouterView
    └── Layout.vue
        └── RouterView
            └── views/pms/product/index.vue
```

这里有一个常被新手忽略的地方：

**嵌套路由需要嵌套的显示出口。**

也就是说，如果 `App.vue` 有一个顶层 `<RouterView />`，那么它可以显示 `Layout.vue`。

但是要让 `Layout.vue` 内部显示商品页面，`Layout.vue` 自己也需要相应的 `<RouterView />`。

你上传的文件并没有包含 `App.vue` 和 `Layout.vue`，所以这个结构需要通过查看它们的实际代码来验证。

## **八、第七部分：页面之间的跳转怎么实现？**

你学习 Router 的目的，最终是能看懂用户点击按钮之后发生了什么。

Vue 3 的 Composition API 中常见写法是：

```
<script setup lang="ts">
import { useRouter, useRoute } from 'vue-router'

const router = useRouter()
const route = useRoute()

function openProduct() {
  router.push({
    name: 'product'
  })
}
</script>

<template>
  <button @click="openProduct">
    打开商品列表
  </button>
</template>
```

两个对象有重要区别：

| 对象          | 主要用途                                      |
| ------------- | --------------------------------------------- |
| `useRouter()` | 获取路由管理器，负责导航操作                  |
| `useRoute()`  | 获取当前路由信息，读取 path、query、params 等 |

假设商品列表跳到编辑商品页面：

```
router.push({
  name: 'updateProduct',
  query: {
    id: 1001
  }
})
```

按你的路由定义，它将对应到：

```
/#/pms/updateProduct?id=1001
```

编辑页面中可以：

```
const route = useRoute()

const productId = route.query.id
```

拿到商品 ID。

但拿到 ID 并不等于已经拿到了商品数据，后面通常还会调用后端 API 查询详情。

你在阅读业务页面时，要把这两个流程分开：

```
点击编辑
    ↓
router.push()
    ↓
进入编辑页
    ↓
useRoute() 读取商品 ID
    ↓
axios 请求商品详情 API
    ↓
页面渲染商品信息
```

这样才能把前端路由与后端接口调用明确地区分。

## **下一步应该学习什么？**

目前从你提供的文件来看，我们已经能确认：

- **定义：** `constantRouterMap` 和 `asyncRouterMap`
- **实例化：** `createRouter()`
- **导出：** `export default router`
- **未确认：** `main.ts` 中的注册、`asyncRouterMap` 的动态添加、导航守卫，以及 `Layout.vue` 内的渲染出口

**我建议下一步直接看项目的** `main.ts`**（或者** `main.js`**）。**

我们先把「Vue 应用创建 → Router 导入 → Router 注册 → 页面首次渲染」这一条主链完全读通，再去分析 `permission.ts` 和动态路由。这样比逐行背路由表更有价值，也更接近你以后阅读企业项目源码时真正需要的能力。
